## 4. Unity & C# Coding Standards

### 4.1 Serialization & Fields
- Use `[SerializeField] private` for inspector-exposed fields instead of public fields.
- Use `[field: SerializeField]` for auto-properties when serialization is necessary.
- Use PascalCase for public properties and methods (`PlayerSpeed`, `CalculateScore()`).
- Use camelCase with an underscore prefix (`_moveSpeed`, `_rigidbody`) for private fields.

### 4.2 Performance & Memory
- **No Allocations in Hot Paths:** Never call `new`, LINQ (`.Where()`, `.Select()`), or string concatenations inside `Update()`, `FixedUpdate()`, or `LateUpdate()`.
- **Cache Components:** Cache `GetComponent<T>()` calls in `Awake()` or `Start()`. Never call `GetComponent` inside update loops.
- **Object Pooling:** For procedural runner tiles, obstacles, collectibles, and VFX, use Unity's `UnityEngine.Pool.ObjectPool<T>` rather than repeated `Instantiate` and `Destroy`.
- **CompareTag:** Use `other.CompareTag("Player")` instead of `other.tag == "Player"` to avoid heap allocations.

### 4.3 Physics & Movement
- Rigidbody physics operations (`AddForce`, velocity modification) must be processed in `FixedUpdate()`.
- Transform-based movement (non-physics) should be scaled by `Time.deltaTime` in `Update()`.

## 5. Input System Guidelines
- Use the **New Input System** (`UnityEngine.InputSystem`). Do not use legacy `Input.GetKey`, `Input.GetAxis`, or `Input.mousePosition`.
- Prefer event-driven callbacks (`performed`, `canceled`) or reading values through configured player input actions.

---

## 6. Asset & Metadata Rules

- **Meta Files (`.meta`):**
  - Every asset and folder in `Assets/` must have a corresponding `.meta` file generated by Unity.
  - Never delete, rename, or move assets via raw file commands without also handling or regenerating their `.meta` files.
  - Avoid editing binary assets (`.unity`, `.prefab`, `.asset`) directly with raw string replacements unless they are simple text-serialized YAML with unambiguous IDs.

---

## 7. Git & Workspace Conventions

- The primary git repository and Unity project root is `CampusRun_Git/`.
- Maintain ignore rules for `Library/`, `Temp/`, `Logs/`, and `UserSettings/`.
- When writing new C# scripts, place them under `Assets/_Scripts/` organized by feature (e.g., `Player/`, `Track/`, `Obstacles/`, `UI/`, `Core/`).
