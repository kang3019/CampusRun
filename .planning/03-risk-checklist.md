## 2. 세부 위험 분석 및 대응 방안

### R-01. 태블릿/노트북 장시간 연속 구동 시 발열 및 프레임 드랍
- **카테고리:** 결과물 / 성능 최적화
- **발생 가능성:** 상 (High) / **영향도:** 상 (High)
- **대응 방안:**
  - **예방:**
    - URP 렌더 스케일을 0.85~0.9로 조정하고, 실시간 그림자 해상도를 Medium/Hard Shadows로 최적화.
    - `Update()` 내 메모리 할당(new, LINQ, string 결합) 전면 금지 및 레인/차량 `UnityEngine.Pool.ObjectPool<T>` 100% 적용.
    - 부스 현장에 노트북 쿨링 거치대 구비 및 예비 태블릿/노트북 1대를 상시 충전 상태로 백업.
  - **발생 시:** 즉시 예비 기기로 교체(핫스왑)하고 과열 기기는 식힌 후 재투입.
- **모니터링 지표:** Unity Profiler 상 1시간 연속 동작 시 60fps 고정 및 Mono Heap 메모리 누수 0B 유지.

---

### R-02. 플레이 시간 초과로 인한 부스 회전율 저하 및 대기열 정체
- **카테고리:** 운영 / 게임 밸런스
- **발생 가능성:** 상 (High) / **영향도:** 상 (High)
- **대응 방안:**
  - **예방:**
    - 길건너 친구들의 독수리 기믹인 **'교수님의 매의 눈'**: 안전 레인에서 3~5초 이상 지체하거나 카메라 밖으로 밀리면 즉시 강제 F학점(게임오버) 판정.
    - 이동 거리가 늘어날수록(200m 이상) 배달 오토바이 스폰 빈도와 속도를 점진 가속하여 평균 플레이 시간을 1분 ~ 1분 20초로 자연스럽게 수렴.
  - **발생 시:** 부스 진행 요원이 대기 인원에게 "1분 안에 빠르게 돌파하는 타임어택!"임을 사전 브리핑.
- **모니터링 지표:** 플레이 테스트 시 1판당 평균 소요 시간 70초 내외 유지 여부.

---

### R-03. 축제 현장 네트워크 마비로 인한 시스템 오작동
- **카테고리:** 기술 안정성
- **발생 가능성:** 상 (High) / **영향도:** 중 (Med)
- **대응 방안:**
  - **예방:**
    - 외부 백엔드 서버나 Firebase 연동을 전면 배제하고, 기기 내부 `PlayerPrefs`를 이용해 TOP 5 기록을 오프라인으로 완벽 저장/조회.
    - 부스 현장 경쟁은 요원이 직접 작성하는 **화이트보드 수기 랭킹판**으로 해결하여 인터넷 연결 의존도 0% 달성.
  - **발생 시:** 비행기 탑승 모드(오프라인)에서도 100% 동일하게 정상 구동.
- **모니터링 지표:** Wi-Fi 연결을 끊은 상태에서 게임 시작 전/종료 후 랭킹 팝업 정상 작동 검증.

---

### R-04. Unity 씬(`.unity`) 충돌로 인한 4인 작업 손실
- **카테고리:** 협업 관리
- **발생 가능성:** 상 (High) / **영향도:** 상 (High)
- **대응 방안:**
  - **예방:**
    - 배포용 메인 씬은 메인 개발자(강민권)만 관리하며, 팀원은 각자 `Assets/_Scenes/Sandboxes/` 내 개별 테스트 씬에서 작업.
    - 모든 장애물(킥보드, 버스, 오토바이)과 레인은 `Assets/_Prefabs/`에 100% 프리팹화하여 동적 인스턴스화.
  - **발생 시:** 충돌 난 씬 파일은 즉시 revert하고 프리팹만 다시 패키징하여 반영.
- **모니터링 지표:** GitHub PR 생성 시 `.unity` 파일 변경점이 포함되지 않도록 사전 코드리뷰.

---

### R-05. 배달 오토바이 돌진 시 불합리한 피격 판정 (억까 방지)
- **카테고리:** 게임성 및 UX
- **발생 가능성:** 중 (Med) / **영향도:** 상 (High)
- **대응 방안:**
  - **예방:**
    - 원작 '길건너 친구들의 기차' 메커니즘을 충실히 반영하여, 오토바이 진입 **1.0초 전 바닥 레인에 선명한 붉은색 경고선/점멸 이펙트**를 표시.
    - 돌진 직전 다급한 "빵빵!" 경적 SFX를 출력하여 유저에게 인지 및 회피할 충분한 시간적 단서를 제공.
  - **발생 시:** 탈락 결과 화면에 "바닥의 붉은 경고선을 주의하세요!" 팁 문구 노출.
- **모니터링 지표:** 테스터 대상 피격 납득도 설문 결과 90% 이상 긍정 평가 확보.

---

### R-06. AI 도구 의존에 따른 발표 Q&A 실패
- **카테고리:** 발표 / 평가
- **발생 가능성:** 중 (Med) / **영향도:** 상 (High)
- **대응 방안:**
  - **예방:**
    - 주요 아키텍처 결정(이벤트 버스, 싱글톤, 오브젝트 풀링, New Input System)을 `.planning/decisions/`에 ADR 문서로 기록.
    - 팀원 전원이 코드를 직접 리뷰하고, "왜 이 기술과 패턴을 선택했는가?"에 대한 모의 Q&A 사전 진행.
  - **발생 시:** 정리된 ADR 문서와 WBS를 발표 슬라이드 부록에 첨부하여 기술적 근거 제시.
- **모니터링 지표:** 팀원 4인 전원이 ADR 문서의 핵심 트레이드오프를 설명할 수 있는지 확인.
